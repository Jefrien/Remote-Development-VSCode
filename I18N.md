# Internationalization

The extension supports English (`en`) and Spanish (`es`). Translations are
stored in `l10n/bundle.l10n.json` and `l10n/bundle.l10n.es.json`.

## Language selection

On first launch, the extension follows the VS Code locale when it starts with
`en` or `es`; otherwise it defaults to English. Users can override this with
the **Remote Development: Change Language** command. The selection is stored
in VS Code global extension state and is restored on the next activation.

After changing the language, reload the VS Code window so command titles and
already-created UI elements refresh as well.

## Adding or changing translations

Keep both bundle files synchronized. Every key in `bundle.l10n.json` must also
exist in `bundle.l10n.es.json`, and placeholders such as `{0}` must remain
unchanged. Use `LocalizationManager.getInstance().t(key, value)` for runtime
messages instead of hardcoding user-facing text.

Command and view titles contributed by `package.json` use
`package.nls.json` and `package.nls.es.json`. Those labels follow the VS Code
locale; runtime messages follow the extension's manually selected language.
